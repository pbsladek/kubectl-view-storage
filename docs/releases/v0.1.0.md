# kubectl-view-storage v0.1.0

The first experimental release of a Rust kubectl plugin for persistent storage
inventory, consumers, reported usage, and observed growth.

## Included

- PVC and PV inventory with declared pod, node, mount and block-device relationships.
- Tree, table, summary, issues and statistics views, configurable grouping and
  sorting, and decimal/binary display units.
- Separate requested, bound, provisioned and filesystem capacities. Shared claims
  are counted once; unknown values remain distinct from zero.
- Optional filesystem and inode telemetry with freshness, coverage, provenance,
  pressure findings and actionable missing-metrics guidance.
- Explicit Prometheus collection with separate credentials and no silent provider
  fallback, plus verified workload-owner filtering and grouping.
- Sequential watch mode, automatic statistics history, saved-report comparisons
  and observed fill-rate estimates.
- Compact JSON (`view-storage/v1alpha1`), CSV, collection costs/timing, offline
  Bash/Zsh/Fish completions for the standalone executable, and `--build-info`.

## Downloads and installation

Archives are provided for Linux and macOS on AMD64 and ARM64. Linux binaries use
musl. Each archive contains `kubectl-view_storage` and the Apache-2.0 LICENSE.
`SHA256SUMS` lists SHA-256 digests for all four archives; verify the digest of your
download before extracting it. Put the executable in a directory on PATH, then run:

```sh
kubectl view-storage --help
kubectl view-storage -n database --view table
kubectl view-storage -n database --view table -u
```

The generated `view-storage.yaml` Krew manifest is also attached. Publication of
this release does not register the plugin in the default Krew index.

## Scope and permissions

Usage collection is opt-in with `-u`. Kubernetes inventory needs read access to
the selected PVCs/PVs and optional related resources. Kubelet telemetry needs
`get` access to `nodes/proxy`; unavailable optional data retains inventory with
explicit reasons. Prometheus uses separately configured credentials.

Driver support determines whether byte/inode observations are available.
Filesystem totals are logical per-claim observations, not physical backend
storage totals. Declared mounts are not runtime mount verification, and fill-rate
estimates describe observations rather than guaranteed forecasts.

This remains experimental. Windows, cloud-CSI certification, and live raw-block
telemetry are outside the validated support set. See the repository's
[compatibility record](https://github.com/pbsladek/kubectl-view-storage/blob/v0.1.0/docs/COMPATIBILITY.md)
for dated platform and driver evidence.
